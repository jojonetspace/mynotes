一、整体架构概览
商品下载有两条路径，最终都汇聚到平台具体的 ItemDownService 实现：


┌──────────────────────────────────────────────────────────────────────┐
│                       手动下载（同步执行）                              │
│  前端弹窗 → OnPostDownShopItem → ShopItemService.DownShopItem         │
│     → CreateItemDownService → 平台.DownByIds / DownByTime             │
│     → ItemConvertService.Convert → Save → Commit                      │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│                       自动下载（异步分段执行）                           │
│  G.ItemDown 定时任务(15min/店铺) → ItemDownService.Down(job)           │
│     → ByTimeTaskBase.StartExecution → 时间步进循环                     │
│        → RequestPage → ConvertModel → Save(ItemToDownload 写队列)      │
│                                                                       │
│  G.ItemQueue 定时任务(5min/店铺) → IItemQueueService.DownByQueue       │
│     → 取出 ItemToDownload → 逐条调 API 获取详情 → PlatformItem 表      │
│                                                                       │
│  G.ItemConvert 定时任务(5min/全局) → ItemConvertBase.Convert           │
│     → Save → Commit                                                   │
└──────────────────────────────────────────────────────────────────────┘
二、手动下载调用链
2.1 前端入口

ShopItemPageModelBase.cs

三、自动下载调用链
3.1 阶段一：G.ItemDown（商品列表下载）
文件：
ItemDownTask.cs


任务配置：
- Code: "G.ItemDown"
- 模式: JobModeStruct.Shop（按店铺拆分）
- 间隔: 900 秒（15分钟）
- 超时: 7200 秒

执行流程：
ItemDownTask.Process()
  ├─ using (DbConnectionAdapter)
  ├─ ItemFactory.GetItemDownService(shopId) → 创建平台下载服务
  ├─ itemDownService.Down(JobInfo)         → 进入时间步进循环
  │   └─ [ByTimeTaskBase.StartExecution]
  ├─ MasterService.WriteAll()
  ├─ DbConnectionAdapter.CommitAndClose()
  └─ JobNotify("G.ItemQueue")             → 通知队列消费任务立即运行
3.2 时间步进机制
文件：
ByTimeTaskBase.cs


StartExecution()
  ├─ CalculateStartTime()  // 从 JobRuntimestamp 获取上次结束时间
  │   └─ DefaultDownStartTime（首次运行默认值，Shopee = UTC -1年）
  ├─ while (!IsAllDataCompleted)
  │   ├─ startTime = JobRuntimestamp.StartTime
  │   ├─ nextRunTimeInfo = GetNextStartTime()  // 按 StepSecond 步进
  │   │   └─ Shopee StepSecond = 5天
  │   ├─ Download(indexPageRequest)
  │   │   └─ do { RequestPage → ConvertModel → results.Add } while (NextPage)
  │   ├─ Save(saveModels)
  │   │   └─ ItemToDownloadDA.ItemToDownloadNewList.AddRange()  // 写入队列表
  │   │   └─ MasterService.WriteAll() + CommitAndClose()  // 提前保存防超时
  │   ├─ if (IsInterrupted) break  // API失败时中断，不推进时间戳
  │   └─ JobRuntimestamp.SaveRunTime()  // 推进时间戳
  └─ return count
关键配置（Shopee）：

StepSecond: 5 天（每次步进 5 天的时间窗口）
OffsetSecond: 60 秒（向前重叠下载，避免时间差遗漏）
DefaultDownStartTime: UTC 一年前
MaxRunSecond: 30 × StepSecond（超过则暂停，下次继续）
3.3 阶段二：G.ItemQueue（商品队列消费）
文件：
ItemQueueTask.cs


任务配置：
- Code: "G.ItemQueue"
- 模式: JobModeStruct.Shop
- 间隔: 300 秒（5分钟）
- 超时: 7200 秒

执行流程：
ItemQueueTask.Process()
  ├─ ItemFactory.GetItemQueueService(shopId)
  ├─ itemQueueService.DownByQueue(JobInfo)
  │   ├─ 从 ItemToDownload 表取出待处理记录
  │   ├─ 调用平台 API 获取商品详情（GetItemBaseInfo 等）
  │   └─ 转换为 PlatformItem 写入中间表
  ├─ MasterService.WriteAll()
  └─ DbConnectionAdapter.CommitAndClose()
关键点：

G.ItemDown 只下载商品 ID 列表（轻量 API），写入 ItemToDownload 队列
G.ItemQueue 从队列取出 ID，调用详情 API 获取完整数据，写入 PlatformItem 中间表
这样分拆的好处：列表 API 可以快速遍历大量时间段，详情 API 按需获取，两者解耦
3.4 阶段三：G.ItemConvert（商品数据转换）
文件：
ItemConvertTask.cs


任务配置：
- Code: "G.ItemConvert"
- 模式: JobModeStruct.Table（全局表级别，按 co_id 分组处理）
- 间隔: 300 秒（5分钟）
- 超时: 7200 秒
- 批次: 2000 条

执行流程：
ItemConvertTask.Process()
  ├─ GetData() → 从 PlatformItem 表取待转换数据（最多 BatchSize 条）
  ├─ 按 co_id 分组
  └─ ConvertByCompany(co_id, items)
      ├─ 按 shop_id 分组
      ├─ UserContext.BuildSingle(co_id) → 创建用户上下文
      └─ foreach shop:
          ├─ ItemFactory.GetItemConvertService(shop)
          ├─ itemConvertService.Convert(platformItems)
          │   └─ [与手动下载共用同一套 ItemConvertBase.Convert 逻辑]
          ├─ MasterService.WriteAll()
          └─ CommitAndClose()
四、手动 vs 自动下载对比
维度	手动下载	自动下载
触发方式	用户点击「确定下载」按钮	定时任务 15 分钟/店铺
入口	OnPostDownShopItem	ItemDownTask.Process()
时间范围	用户指定（商家时区）	从上次结束时间到当前（UTC 步进）
执行模式	同步，HTTP 请求内完成	异步三段式：Down → Queue → Convert
数据存储路径	DownByIds/DownByTime → 直接 ItemConvertService 入库	先写队列 → 再消费 → 再转换入库
IsManualDown	true	false
l_data 处理	清空 l_data + listing_status=Consistent	保持原值不变
错误处理	直接抛异常返回前端	设置 IsInterrupted，不推进时间戳，下次重试
时区处理	前端传商家时区 → 转为服务器本地时间	UTC 直接 .ToLocalTime()

六、注意事项与经验教训
时区处理（已修复）：手动下载传入的是商家时区时间（Kind=Unspecified），在 Shopee DownItemByTime 中通过 DateHelper.GetDateTimeByTimeZone 转换为服务器本地时间，再传给 ShopeePlatform.GetProducts。

定时任务不经过 ShopItemService.DownShopItem：自动下载直接走 ItemDownByTime.Down(job) → StartExecution() → RequestPage()，不走 ShopItemService 的分派逻辑。

自动下载三段式解耦：

G.ItemDown：只取列表（商品 ID），写入 ItemToDownload 队列
G.ItemQueue：消费队列，调详情 API，写入 PlatformItem 中间表
G.ItemConvert：从中间表取数据，执行 Convert → Save 入库
这样设计使得每个阶段可以独立重试，不会因为详情 API 超时而阻塞列表遍历。

新增平台需检查 SupportDownPlfs：此列表控制手动下载弹窗和复制弹窗的店铺可见性。

手动下载的特殊行为：IsManualDown=true 时，下载成功后会清空 l_data（刊登副本）并设置 listing_status = Consistent，意味着刊登数据与平台一致。
